What triggers this workflow to run? (Look at the on: section) It runs when code is pushed to main (check the on: section to confirm, it may also run on pull requests). Deployment only happens on a push to main.
What are the four main steps this workflow performs? (List each step name) Checkout code, Validate HTML, Check links, Upload artifact.
What does the "Checkout code" step do and why is it necessary? It copies the repo's files onto the runner using actions/checkout@v4. The runner starts empty, so without it there'd be nothing to validate or deploy.
What is the purpose of the environment configuration? It sets the environment to github-pages and gives the deploy job a URL output. This lets GitHub track the deployment and show the live site link, and with the pages: write and id-token: write permissions it lets the job publish to Pages.
How does this automated deployment improve reliability compared to manual deployment?  It runs the same steps every time, validates the HTML before anything goes live, only deploys if the build job passes, and logs every run so failures are easy to trace. Less human error than doing it by hand.
